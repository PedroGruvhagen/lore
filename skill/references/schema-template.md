# Lore Schema

This file documents the structure and maintenance rules for this lore instance. It is generated by `lore.py bootstrap` and should not be deleted.

## Directory Structure

```
lore/
├── index.md        # Auto-generated table of contents (rebuilt by `lore.py index`)
├── log.md          # Append-only changelog of all lore operations
├── schema.md       # This file: structure and rules
├── .search.db      # SQLite FTS5 search index (derived, gitignored)
├── .gitignore      # Ignores .search.db
├── pages/          # One markdown file per topic
│   ├── anthropic-api.md
│   ├── openai-api.md
│   └── ...
├── entities.json   # Entity registry mapping slugs to aliases (auto-generated + manual)
└── sources/        # Raw ingested source material (gitignored in project lore)
```

### File Purposes

- **index.md**: Machine-generated. Lists every page with its title, category, and one-line summary. Rebuilt by running `lore.py index`. Read this first when querying lore.
- **log.md**: Append-only log of all changes. Format: `- {ISO-8601} | {message}`. Never edit past entries.
- **schema.md**: This file. Documents structure and rules.
- **.search.db**: SQLite database with FTS5 full-text search index. Derived artifact, can be deleted and rebuilt from pages at any time.
- **pages/**: One `.md` file per topic. Each file follows the format in `references/page-format.md`.
- **sources/**: Raw source material (PDFs, HTML snapshots, text files) ingested to create pages. Gitignored in project lore.

## Categories

| Category | Description | Example Pages |
|----------|-------------|---------------|
| `api-reference` | API endpoints, model IDs, SDK versions, pricing | anthropic-api, openai-api |
| `best-practices` | Current recommended approaches and patterns | python-packaging, nodejs-typescript |
| `deprecations` | Deprecated models, APIs, patterns, replacements | deprecated-patterns |
| `tooling` | CLI tools, build tools, package managers | (user-created) |
| `infrastructure` | Servers, services, deployment, CI/CD | (user-created) |
| `custom` | Anything that doesn't fit the above | (user-created) |

## Maintenance Rules

1. **Never delete a page without logging.** Before removing any page, add an entry to `log.md` explaining why. Move content to another page if applicable.

2. **Always update `last_verified`.** When you verify or update a page's content, set `last_verified` to today's date (`YYYY-MM-DD`).

3. **Sources are append-only.** Never remove a source URL from a page's frontmatter. If a source becomes invalid, add a note but keep the URL for provenance.

4. **Rebuild index after changes.** After creating, updating, or deleting pages, run `lore.py index` to keep `index.md` and `.search.db` in sync.

5. **Log everything.** Every meaningful operation (page create, update, delete, refresh, ingest) gets a `log.md` entry via `lore.py log`.

6. **Keep pages focused.** One topic per page, under 200 lines. Split if larger.

7. **Cross-reference, don't duplicate.** Use `[[page-slug]]` links instead of copying content between pages.

8. **Lore overrides training data.** When lore and Claude's training data disagree, lore wins. That is the entire point of this system.

9. **Check for contradictions.** When updating facts that appear on multiple pages, verify consistency across all pages that reference the same fact. Contradictions between pages erode trust in the knowledge base.
